# v18.8.0 — Provider reliability and reviewed metadata changes

Imported SickChill provider ordering was incorrectly turning disabled providers back on. TV Manager now honors each provider's enabled flag and its daily/backlog switches. Settings → Search Providers can edit imported and custom providers, preserve masked keys, remove connections, and test both capabilities and authenticated search. Edits preserve extended SickChill fields and reject stale forms. Duplicate connection names are rejected.

The shared Newznab/Torznab adapter accepts base URLs or existing API endpoints, detects XML account/API errors, refuses news-server addresses, pages through bounded results, and falls back to text search when TV search is unavailable. HTTP 429 pauses requests immediately; diagnostics protect API credentials. Season-pack searches share this adapter. A configured NZBFinder connection passed capability discovery and a non-download authenticated search. Two suspended legacy providers were actually disabled in the imported settings; their order-list entries no longer re-enable them. Newshosting's configured endpoint responded as an NNTP news server, not an HTTP indexer. Production settings were not changed.

Show Detail → Edit Show Settings → Change Metadata Source or Episode Order provides a signed preview for existing TMDb/TVDB libraries. Every existing episode must map uniquely to the new list. Apply preserves episode IDs, file paths, statuses and linked history, handles numbering swaps atomically, records the previous metadata, and rejects stale previews or active downloads. Unmapped episodes block the operation. File renaming is a separate existing workflow. Scene numbering is cleared for review after migration. Both metadata-refresh routes now use the same guarded implementation, and a failed TMDb season request cannot produce a partial successful refresh.

All stored show aliases and XEM scene destinations are searched. Where multiple scene episodes map to one library episode, single-file retrieval is blocked pending numbering review: automatic assembly of split scene files is still unsupported. The change does not claim complete anime parity.

Added Deluge daemon and put.io transfer creation and polling. All five native adapters, including uTorrent, rTorrent and Download Station from v18.7.0, are now connected to the main connection-test and status-polling workflows. This corrects a wiring omission in v18.7.0. Deluge daemon disables automatic RPC replay and verifies returned torrent identity. put.io receives descriptor bytes for HTTP torrent releases and records the remote transfer ID.

For Deluge daemon, use the daemon host with port 58846 in the torrent connection address, daemon username/password, and enable the Label plugin if a label is configured. Its RPC library uses Deluge's self-signed TLS protocol without hostname certificate verification; it is intended for a trusted daemon connection. For put.io, the password field holds the OAuth token, the optional path is a numeric destination folder ID, and an imported username can select a root folder by name. The host field is unused. Cloud-file synchronization into the completed-download folder must be configured separately. put.io's paused option is rejected before a transfer is submitted.

Show controls now load their scripts using the release version, so an old fixed script URL cannot hide newly added settings. The metadata review loads destination choices only for the focused row rather than duplicating the entire episode list in every row.

Validation results are recorded in `RELEASE_MANIFEST.json`. Browser verification used an isolated synthetic library: saved a disabled provider with independent daily/backlog choices; opened migration through Show Settings; confirmed an unresolved match was blocked; matched and migrated all 35 episodes; verified the recorded file content/path and downloaded status were preserved. Live provider checking requested no downloads. Real Deluge daemon/put.io service acceptance and a new Windows executable build are not claimed for this release.

Restart TV Manager normally and refresh browser pages to activate the published source. The production process was not restarted. Full SickChill parity remains incomplete; the current source audit explicitly lists outstanding integrations and behaviors.
